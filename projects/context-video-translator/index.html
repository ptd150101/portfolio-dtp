01 · Problem

Translation latency is only one part of the problem.

Most subtitle translators look simple from the outside: read text, call a model, display the result. In practice, a useful video-learning tool must coordinate a moving caption timeline, inconsistent platform APIs, model latency, seeking, fullscreen remounts and language changes without flashing stale or half-complete content.

The core product is not “LLM translation.” It is a realtime orchestration layer that keeps platform timing, model output and the rendered overlay in one consistent state.

Three product constraints

  1. Context matters. Spoken lines often depend on neighboring cues, so isolated translation produces ambiguous pronouns, inconsistent terminology and unnatural phrasing.
  2. Platforms expose captions differently. YouTube uses timedtext in JSON3/XML while Udemy can surface signed VTT URLs, lecture APIs, text tracks or observed resource requests.
  3. Pending state must not become visual noise. The source and translated line should update atomically rather than showing a source-only flash, placeholders or a stale language track.

02 · Architecture

Three execution contexts with explicit responsibilities.

The extension separates page-world interception from content orchestration and background model access. This is necessary because browser content scripts cannot directly observe every application object or network call made by the page.

Platform adapter

Runs in the page’s MAIN world and observes YouTube timedtext, Udemy fetch/XHR responses and caption API candidates.

Message bridge

Uses scoped window.postMessage events to move validated caption payloads into the isolated extension context.

Cue normalizer

Parses JSON3, XML and WebVTT into stable timed cues with normalized IDs, timing and source language.

Translation scheduler

Selects the current and upcoming untranslated cues, adds surrounding context and handles urgent fills after seek.

Background worker

Calls any OpenAI-compatible endpoint, validates numbered output, retries errors and reads/writes IndexedDB cache.

Overlay renderer

Renders the bilingual subtitle atomically, adapts height, supports fullscreen remounting, layout editing and Japanese study analysis.

Why this boundary matters

Network interception remains platform-specific and disposable. Translation logic remains provider-agnostic. Rendering receives normalized cues rather than raw YouTube or Udemy payloads. That separation makes a future Netflix adapter possible without rewriting the model client or subtitle UI.

03 · YouTube

Race-safe capture instead of DOM scraping.

The YouTube adapter patches both fetch and XMLHttpRequest for timedtext requests. It reads the selected caption track from the player, attaches a selection epoch to captured responses and delays delivery briefly while the player state settles.

The stale-response race

When a viewer switches from one caption language to another, an old network request can finish after the selection has already changed. Rendering that response creates a mixed-language or “jumping back” subtitle experience.

Track selection timeline
Old track response startsSelection changesResponse revalidatedOnly matching track delivered

JSON3 replacement events

Translated JSON3 can contain an original event followed by a replacement event for the same caption window. Concatenating every event displays both languages. The adapter compares event IDs, window IDs, time deltas and overlap ratios, then removes only the stale event while preserving the final state YouTube would render.

Rejected

Reading visible caption DOM

DOM text is late, presentation-specific and vulnerable to rolling-caption replacement behavior.

Chosen

Capture native timedtext

Native payloads preserve cue timing and provide a stable source before YouTube’s visual renderer mutates the DOM.

04 · Udemy

A multi-source caption discovery pipeline.

Udemy courses do not expose captions through one reliable public surface. The adapter therefore treats discovery as a scored fallback pipeline rather than a single selector.

Observed VTT

Capture signed WebVTT responses seen in fetch or XHR requests.

Lecture API

Request the active lecture asset and extract caption objects with refreshed signed URLs.

JSON walk

Bounded traversal of likely caption-bearing API responses while rejecting bare filenames that are not fetchable URLs.

Native tracks

Fallback to video textTrack cues and HTML <track> elements when available.

Performance entries

Inspect loaded resource URLs for VTT assets that may have completed before the extension attached its interceptor.

Fetch context fallback

Some signed CDN VTT URLs reject credentialed CORS, while lecture APIs require the authenticated page context. The content orchestrator selects credentials by destination and can fall back across page-world fetch, content-script fetch and background fetch.

The adapter validates that a response actually looks like WebVTT before parsing it. If the body is JSON, it searches for a better caption candidate instead of treating an API response as a subtitle file.
05 · Realtime scheduler

Translate ahead, prioritize now, preserve context.

The scheduler fills a moving window ahead of playback. It chooses untranslated cues from the current position through the configured horizon, puts the active cue first and batches only the number the provider can handle safely.

Cached / translatedCurrent cue: highest priorityUpcoming batch+60 seconds

Context construction

Each request contains the numbered lines to translate plus up to five previous and five future cues marked as context-only. The background worker requires the model to return exactly the same number of numbered lines and rejects missing output.

translation-request.txt
Previous context, do not translate:
- さっき駅に着きました。
- 友達を待っています。

Future context, do not translate:
- 一緒に昼ご飯を食べます。

Translate these numbered lines into Vietnamese:
[1] もうすぐ来ると思います。
[2] 今日は少し寒いですね。

Atomic rendering

The overlay reserves stable layout space while a translation is pending but does not expose a visible placeholder. The source and translated state update together, preventing the subtitle from looking complete while still showing untranslated text.

Local cache

IndexedDB keys include provider URL, model, source language, target language and normalized source text. Entries have a configurable TTL and a maximum count, so replaying or seeking through a previously watched video avoids unnecessary model calls without mixing results across configurations.

06 · Japanese study mode

Local language analysis layered onto the caption timeline.

Study mode uses Kuromoji when available and falls back to a lightweight rule engine while the dictionary loads or when users prefer a smaller setup. Token analysis is cached and mapped into reader-friendly categories such as noun, verb, particle, auxiliary and adjective.

UX choices

  • Furigana can appear for all Kanji tokens, only the currently spoken chunk or on hover.
  • Karaoke progress fills the whole original line instead of flashing many tiny grammar blocks.
  • Dynamic height measures the rendered subtitle so ruby text and two-line translations are not clipped.
  • The subtitle output itself has a configurable background and can be dragged directly in normal mode.
07 · Reliability

Failure handling designed into the visible experience.

Failure modeHandling
Old caption response finishes lateRevalidate selected track and selection epoch before delivery.
JSON3 contains stale replacement eventDetect matching timing/window pairs and keep the final event.
Model returns wrong numberingStrict parser, bounded best-effort only after actual model output, never silent network fallback.
User seeks into an untranslated cueUrgent current-cue scheduling before continuing the ahead window.
Udemy signed VTT fetch failsFallback across page, content and background execution contexts.
Fullscreen or SPA navigation remounts videoObserve route/video changes and recreate the overlay against the active player.

Known limitations

  • The platform must expose captions or a transcript; the extension is not a speech-recognition engine.
  • Translation quality and latency depend on the configured model or provider.
  • Platform DOM and API changes can require adapter updates.
  • Netflix is a planned adapter, not a current supported platform.
  • The current prototype has deeper implementation coverage than automated test coverage.
08 · Next iterations

From a capable prototype to a maintainable product.

Refactor platform adapters behind a common interface

Extract YouTube and Udemy capture, discovery and normalization into explicit modules so the orchestration layer depends only on normalized cue events.

Add parser and scheduler fixtures

Build deterministic tests for JSON3 replacement handling, XML/WebVTT parsing, numbered model output, cache keys, seek priority and caption-track switching.

Package for Chrome Web Store

Finalize privacy documentation, remove overly broad permissions where possible, add release automation and produce a stable onboarding flow.

Expand learning workflows

Export bilingual transcripts, track per-course vocabulary and optionally summarize long-range context rather than sending only neighboring cues.

Add a Netflix adapter

Implement as a separate platform adapter without coupling its capture mechanism to YouTube or Udemy assumptions.

The most valuable next step is not another visible feature. It is converting proven runtime behavior into modular adapters and repeatable fixtures.
